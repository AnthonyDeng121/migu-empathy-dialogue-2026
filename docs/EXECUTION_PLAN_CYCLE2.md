## 并行与一次性交接原则

1. **同周期四人独立开工。**仅使用已有工程及前周期产物，不安排 A→B→A 或 C→B→C 的往返等待。
2. C/D 完整完成训练、预测、自检及初步结论，在周期末一次性交付；B 下一周期独立复核新产物。
3. A 对尚无新权重的接口用旧 checkpoint 或假模型验证；真实权重接入放到交付后的周期。
4. 普通反馈批量进入后续周期，不要求当期反复重跑。数据泄漏、权重损坏或无法运行等阻塞缺陷仍应停止相关结论，记录一次修复交接。
5. 前序迟交时使用预先约定的旧基线或完成独立子任务，不追要半成品、不让整个周期空等。

以下为**初步预算区间，不是实测、承诺或已获额度**，按首批短跑修订。数据准备、下载、上传、依赖与代码检查在启动付费时段前完成。

首批优先画像 v1、最新版条件筛选及无条件 SFT 的必要部分。追加顺序：完成必要训练 → 入围候选完整比较 → 有依据的额外实验。开机前检查余额能完成任务或具备可恢复检查点，避免无保护中断；恢复实现未验证前优先保证单次训练有足额时长。

- A 大部分配置、加载、恢复、组装、打包与回归在 CPU/假模型/已有文件上完成，只为少量真实加载和生成排 GPU。
- B 指标计算、切片、复核和统计使用已有预测与 CPU，只有 T6 必要完整生成排 GPU。
- C 保存概率供阈值/融合复用；D 的消融固定小规模输入，最终只评少数入围候选。历史结果复用必须核对输入、权重、配置和预处理指纹。
- 正式端到端计时不使用历史缓存，断点恢复累计时间与冷启动计时分开记录。
- 公共卡按开工前固定时段给 C/D，时段外推进本岗位 CPU 工作，不临时轮流交还再等回来。资源不够先缩减可选候选，必要任务明确追加。
- 暂不安排更大基座网格、重复生成长度探针、多种量化/合并全量比较；不省必要画像和回复训练。

## 本地验证与采用规则

1. 沿用 B1 数据与 ID，固定 2,354 条回归集并承认它已被历史实验使用。训练内按 conversation_id 隔离学习/校准数据，阈值、融合和 checkpoint 在训练内选择。
2. 筛选清单在看新结果前确定，覆盖长短历史、画像空非空和主要/稀有情感；小样本用于淘汰无效方案，不作为最终提分证明。
3. 若重分训练数据，说明旧基线是否见过对应样本，必要时重训公平对照；没有新盲测数据不保证隐藏测试提升。
4. 画像同集比较空数组、旧头、新模型；报告逐维和宏 exact match、非空表现、micro/macro F1、precision/recall及预测非空率。T1 写采用门槛，不能看结果后换主指标。
5. 情感报告 Accuracy、Macro-F1、逐类支持数及 mixed/care；回复报告现有本地 BLEU/ROUGE、场景/长度切片和内容误例。本地指标不是官方分数。
6. 条件仅取目标轮及此前可用信息；不用验证真值、未来回复或验证集检索。单项实验只改一个因素，组合效果另比较。
7. OI 无分数/排名反馈，不安排线上试分。A/B 根据本地整体、切片、稳定性和成本选择，收益微弱或方向冲突时明确不确定性并保留成功版。
