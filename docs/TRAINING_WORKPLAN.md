# 训练任务、耗时校准与验收

本文件与 EXECUTION_PLAN.md 配套，所有时间为 Asia/Shanghai。下面的小时数是排程预算，不是已测性能。队员表示可完成分配任务，当前关键约束是 40 个 RTX 4090 卡时、卡券失效时间、模型体积与机器运行时间。模型选型必须受实际资源和赛事许可约束。

2026-10-13 账户页确认两张 RTX 4090 券各 20 卡时，共 40 卡时，失效时间分别为 2026-10-20 16:02:53 与 16:02:55；另有10小时无卡模式、30GB私有镜像免费额度和20GB共享文件存储免费额度。无卡券不计入GPU预算。团队决定等 C/D 初版脚本、数据加载与依赖清单可直接运行后再开实例，避免把卡时用于现场写代码和下载排错。

训练环境候选为通用 `PyTorch 2.5.1 / Ubuntu 22.04 / Python 3.11 / CUDA 11.8`；正式参赛实例必须从 `vLLM:0.19.0-ubuntu22.04-p3.12-cuda12.8` 大赛专属公有镜像创建。前者只训练，后者负责最终集成、离线回归、保存和上传参赛镜像。

## 用测速替换估算

1. C/D 记录 GPU 型号/显存、精度、batch、梯度累积、最大长度、有效训练样本数和 epoch 上限；样本数以 B1 转换产物为准，不把 18,657 直接当成所有任务都可用。
2. 小样本先验证 loss 有限、梯度有效、权重改变、保存后可加载。先 warm-up，再测至少 50 个优化器 step；较慢生成任务可测 20 个，但标记估计置信度低。记录平均每 step 墙钟时间。
3. 单 GPU 的 steps/epoch = ceil(ceil(N / micro_batch) / accumulation)。多卡使用训练器实际 dataloader 长度和 step 数，不直接套单卡公式。ETA = 剩余 steps × 秒/step + 验证/保存耗时，再留 30% 故障余量。
4. 前 50–100 个验证样本测端到端吞吐，估算全量评测时间；按约 2,354 个预测点预算，最终以转换后实际数量为准。训练和推理分开预留卡时。
5. A 在 T0+4h 和每轮结束更新队列、预计完成、剩余卡时。按 GPU 数量计算卡时，双卡跑 4h 占 8 卡时；平台赠送额度必须读取实际账户，不能引用宣传额度当成可用余额。
6. 预测超出 10/14 候选门槛时，先缩短上下文、减少首轮 epoch 或选择更小的可许可模型，重新测速并记录改变。保留完整训练数据作为优先方案；必要抽样需固定 seed、conversation 分组，并明确标记为小样本候选。

## 单卡与多卡队列

- 单卡：C 情感短跑/首轮 → D 原模型小样本/微调首轮 → C 画像首轮 → B/D 生成全量评测。C 画像是否提前由 ETA 和 D 首轮截止决定；A 在每个任务结束时明确交接。
- 多卡：确认每路在单卡显存内可运行后，C/D 分卡并行；一个任务必须多卡时按独占排队，不把剩余卡虚构成可并行资源。
- GPU 尚未启动：这不是资源缺失，而是节约卡时的团队决策。C/D 先完成可运行初版、CPU/MPS dry-run、固定模型 revision 和依赖清单；A 验收“一开机即可短跑”后创建1卡实例。未开实例前不能声称平台训练已启动。
- 不启动会消耗最后回归/提交预算的搜索。卡时不足时保留已验证训练候选和回归所需资源。

## 模型研究要回答的问题

| 负责人 | 优先问题 | 最小对照及采用依据 |
|---|---|---|
| C，B评测 | 情感模型是否学到有效信号，是否受多数类主导 | 同一全量验证集对比多数类；已有情感多数类 31.90%，先复核后作为下限参照；同时记录 Macro-F1/每类召回 |
| C，B评测 | 画像是否优于空集合，共享训练是否带来负迁移 | 三维 exact-match 分别对比空集合/多数类；已有均值 62.83%，先复核；单任务可用后才做共享消融 |
| D，B评测 | 微调是否提高共情回复而没有损害输出格式 | 检索、未微调模型、微调模型三路同集比较；记录字符诊断指标、合法率、人工复核固定50例、推理耗时 |
| D，C复核 | 情感/画像条件注入是否帮助回复 | 无条件注入与预测条件注入比较；不能把验证真值标签传给最终候选冒充真实部署结果 |
| D，A核验 | 当前输入能支持什么记忆能力 | 使用截止目标 turn 的历史；没有 memory bank 就不伪造 mem ID，memory_refs=[]；官方提供规范后再实现引用 |

每条训练线只选一个主模型和一个必要替代，不安排从零预训练。预训练模型与外部数据的许可边界待官方确认；记录许可和使用来源，未明确的方案标记为待确认候选，不能宣称合规。首次实验使用官方训练集；不要为追赶进度引入未经确认的外部/合成训练数据。

## 交付与审查

每轮实验包含：代码 commit 与 dirty 状态、训练/验证哈希、模型 revision/许可、seed、配置、依赖精确版本、硬件、开始/结束/卡时、loss/验证曲线、最佳 checkpoint、停止原因、权重 SHA-256、复现命令、全量指标与前100条性能报告。训练期间同步保存日志和技术说明，不把材料工作全部留到最后一天。

C 提供 emotion_label 和三画像维度；D 提供 response_text 与 memory_refs；A 组装统一输出并验证全量 ID/顺序/行数。导出模型、tokenizer、adapter/合并权重、配置和所需运行代码必须一起离线可用。

A→B→C→D→A 闭环用于 PR 验收，不用来把 GPU 训练串行等待一圈：B 数据契约小样本先可供冒烟，正式数据 v1 通过检查后即可训练；其他 PR review 与训练并行。正式镜像只纳入已通过接口测试和复核的产物。

训练完成不等于任务 Done：有权重、指标和日志才进入 Integration Gate；按执行计划复核、通过 CI 并合并 main 后才 Done。
